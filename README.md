# 打地鼠大亂鬥 🔨🐹

可愛風打地鼠。**11 種地鼠**，壞人敲下去加分、好人敲下去扣分；
單機有四段電腦難度，線上最多 **5 個人共用同一組地洞**，同一隻地鼠 **誰先敲到誰得分**，
右上角有設定、左側有即時統計與聊天室。手機／平板／桌機、直向橫向都能玩。

---

## 最快開始（在自己電腦上玩）

雙擊 **`啟動遊戲.bat`**（第一次會自動 `npm install`），瀏覽器會自己打開
<http://localhost:3030>。

視窗裡會印出「同網段」網址，例如 `http://192.168.1.23:3030` ——
同一個 Wi-Fi 下的手機、平板、其他電腦輸入這個網址就會進到同一個大廳，可以直接開房對戰。

指令版：

```bash
npm install
npm start           # http://localhost:3030
```

## 玩法

| | |
|---|---|
| 一局長度 | 預設 **60 秒**，可選 60／75／90（單機在設定裡選，線上由房主決定）。分三階段：**熱身**（前 1/3）→ **加速**（中間 1/3）→ **狂亂**（最後 1/3）。切點按比例算，換長度一樣走得完三段 |
| 盤面 | 以正方形為主，9（3×3）／12（4×3）／16（4×4）／20（5×4）／25（5×5）／36（6×6）個地洞。單機在設定裡選，線上由房主決定。洞愈多，同時冒出來的地鼠也愈多、冒得愈快。實際排成幾乘幾由裝置的畫面形狀決定 |
| 加分 | 敲到「壞人」地鼠 |
| 扣分 | 敲到「好人」（小雞、兔子、農夫爺爺、貓店長） |
| 敲空 | **不扣分**，只會拉低命中率 |
| 連擊 | 連續敲中壞人，每 5 連擊 +10%，最多 +50%；敲到好人連擊歸零 |
| 線上 | 全部人看同一組地洞，同一隻地鼠先敲到的人得分，慢一步只會敲到空氣 |

### 地鼠圖鑑

**壞人（敲下去加分）**

| 地鼠 | 分數 | 要敲幾下 | 特色 |
|---|---|---|---|
| 小土鼠 | +10 | 1 | 最常見的小嘍囉 |
| 疾風鼠 | +25 | 1 | 戴護目鏡，只露臉 0.6 秒 |
| 鐵盔鼠 | +44 | 2 | 第一下只會把鐵盔打歪 |
| 炸彈鼠 | +60 | 1 | 分數高但停留很短 |
| 彩虹鼠 | +50 | 1 | 敲中後 **6 秒內你的正分加倍** |
| 大王鼠 | +96 | 3 | 又大又肥，敲倒的最後一下多拿一份 |
| 黃金鼠 | +120 | 1 | 全場最高分，只露臉 0.54 秒 |

**好人（千萬不要敲）**

| 好人 | 分數 |
|---|---|
| 小雞 | −15 |
| 小兔子 | −20 |
| 農夫爺爺 | −35 |
| 貓店長 | −50 |

> 好人和壞人的差別**不只有顏色**：好人頭後面有一圈綠色虛線光環、圓耳朵、笑瞇瞇的眼睛，
> 角落的分數標記是紅底的「−」；壞人是尖耳朵、怒眉，標記是綠底的「+」。
> 色彩辨識不便時，可以在設定裡打開「分數標記放大」。

### 操作

- **觸控／滑鼠**：直接按地洞，**按下去就算**，不用等放開（線上搶打差的就是這幾十毫秒）。
- **鍵盤**：Tab 或方向鍵移到地洞，Enter／空白鍵敲下去。
- **螢幕閱讀器**：每個地洞都會唸出目前是哪一種地鼠、加分還是扣分、還要敲幾下。

## 模式

### 單機練習
選難度、盤面大小與電腦對手數量（0～4 個），一個人也能挑戰高分。

**難度同時決定兩件事**：地鼠的節奏（冒多快、停多久、同時幾隻），以及電腦對手的強弱。
覺得地鼠咻一下就縮回去，往下選一級就好。

| 難度 | 地鼠停留 | 冒出間隔 | 電腦反應 | 電腦看走眼 | 90 秒平均分（電腦單獨玩） |
|---|---|---|---|---|---|
| 🍼 超級新手 | ×2.4 | ×1.9 | 980ms | 46% | 約 340 |
| 🌱 簡單 | ×1.6 | ×1.35 | 640ms | 34% | 約 1300 |
| 🔥 普通 | ×1（基準） | ×1（基準） | 430ms | 16% | 約 3500 |
| ⚡ 困難 | ×0.75 | ×0.8 | 300ms | 5% | 約 6300 |

「地鼠停留」「冒出間隔」是乘在三個階段的基準值上的倍率。實測在平板上一隻地鼠平均停留：
超級新手 2.0 秒、普通 1.0 秒、困難 0.6 秒。

電腦對手的差別是「看得多快、認得多準、手多穩、會不會挑高分的打」，不是只換名字。
槌子還要花時間從上一個地洞移過去（每跨一格 40～140ms），所以電腦不會瞬間橫掃全場。

### 線上對戰
最多 **5 個座位**（真人和電腦對手共用這 5 個位子），另外可以有最多 19 個觀戰者。

- **房號**：5 碼，不含容易看錯的 `0 O 1 I`，可以用嘴巴唸給隊友聽。
- **房主設定**：一局長度、難度、盤面大小由房主在準備階段決定，開打後鎖住。
- **自動關房**：最後一個人離開就立刻關掉，不留空房佔房號。斷線的人座位保留 60 秒等他回來，過期才算真的沒人。
- **觀戰**：席位滿了或對局已經開始，進來的人會**明確地**變成觀戰身分（不會默默被當成玩家），
  觀戰者看得到完整盤面與即時統計，但沒有出手權限。
- **邀請連結**：房主可以產生指定身分（玩家／觀戰）的連結，有使用次數與有效期限，也可以隨時撤銷。
  連結失效時會明白說是「過期」「被撤銷」還是「次數用完」。
- **私人房**：只能用邀請連結進來。
- **斷線重連**：座位會保留一分鐘，用同一台裝置重新整理就會回到原位，分數不會被清掉。
- **聊天室**：有防洗版與房主禁言。

## 畫面配置

左邊一條窄側欄同時放**即時統計摘要**和**聊天室**，其餘空間全部留給盤面。

摘要刻意只留三樣東西，剩下的空間都給盤面：

1. 一行房間／模式資訊（房號、你的身分、幾人）
2. 即時排行（名次、名字、分數，有連擊時才多一個小字）
3. 一行自己的表現（命中、誤敲、準度、最佳連擊）

階段和剩餘時間交給上方 HUD，不在側欄重複佔位。
還沒開打的線上房間裡，摘要一樣有東西看：房號、身分、座位、這一局的設定，
以及目前房裡每個人的準備狀態。HUD 的秒數也直接顯示這一局實際會有多長。
窄螢幕的 HUD 只顯示「熱身／加速／狂亂」，讓時間、階段、分數排得下同一行。

- **桌機／平板橫向**：側欄固定在左邊（178～232px，約佔 14～20% 寬），盤面吃滿剩下的空間。
- **手機／平板直向**：側欄變成從左邊滑出的抽屜，左下角有 📊 和 💬 兩顆浮動按鈕（聊天有未讀數），
  盤面吃滿整個寬度。盤面等比縮放後周圍留下的空白會放上**即時排行浮條**
  （直向貼在盤面上方、橫向貼在左側），打到一半不必開抽屜就知道誰領先；
  浮條不吃點擊，也不會壓到地洞。
- **右上角**永遠有 ⚙ 設定按鈕（在安全區內，不會遮住遊戲控制），按下去開 Modal 彈窗。

設定彈窗裡有：背景音樂、音樂音量、遊戲音效、音效音量、聊天提示音、震動回饋、
減少動態、分數標記放大、恢復預設。
遊戲偏好設定存在這台裝置的 localStorage，重新載入後仍保留。

音樂與音效都是 Web Audio 即時合成，**沒有任何外部音檔**，所以不會有授權問題也不會載入失敗。
要換成正式音檔時，只要保留 `Sound.play / startBgm / stopBgm` 這幾個介面即可。

## 佈署：伺服器放 Render，前端放 GitHub Pages

GitHub Pages 只能放靜態檔案，**跑不動 `server.js`**。所以架構是：

```
   前端（GitHub Pages）  ──── WSS / HTTPS ────>  伺服器（Render 免費方案）
   靜態 HTML/CSS/JS                              Express + Socket.IO
```

前端也可以整包由 `server.js` 自己送出來（開 `npm start` 就是這樣），
那種情況下 `config.js` 會自動用同源，什麼都不用設定。以下是「前後端分開」的做法。

這個 repo 佈署出來的實際位置：

| 東西 | 網址 |
|---|---|
| 原始碼 | https://github.com/PJH-Eric/whack-a-mole |
| 前端（GitHub Pages） | https://pjh-eric.github.io/whack-a-mole/ |
| 伺服器（Render） | Render 建好之後填進 repo 變數 `GAME_SERVER_URL` |

### 步驟 1：把伺服器放上 Render

1. 把這個 repo push 到 GitHub。
2. Render → **New → Blueprint** → 指到這個 repo。`render.yaml` 已經寫好了
   （Node 20、`npm ci --omit=dev`、`node server.js`、健康檢查 `/health`）。
3. 部署完成後把網址記下來，例如 `https://whack-a-mole.onrender.com`。
4. 在 Render 的 **Environment** 把 `GAME_ALLOWED_ORIGIN` 設成你的 Pages 來源，
   這個 repo 是 `https://pjh-eric.github.io`（只要來源，不含路徑）。
   **這一步不做，瀏覽器會因為 CORS 擋掉連線。**

可設定的環境變數：

| 變數 | 預設 | 用途 |
|---|---|---|
| `PORT` | 3030 | 監聽埠（Render 會自動注入） |
| `HOST` | 0.0.0.0 | 監聽介面 |
| `GAME_ALLOWED_ORIGIN` | `*` | 允許連進來的前端來源，逗號分隔。**正式環境請明確設定** |
| `ROUND_MS` | 60000 | 新房間的預設一局長度（房主仍可改成 60／75／90 秒） |
| `COUNTDOWN_MS` | 3000 | 開賽倒數 |

### 步驟 2：把前端放上 GitHub Pages

1. Pages 本身不用手動開 —— workflow 裡的 `configure-pages` 帶了 `enablement: true`，
   第一次跑就會自己把 Pages 開起來、來源設成 **GitHub Actions**。
   （如果組織政策擋掉自動開啟，就手動進 **Settings → Pages → Source** 選 **GitHub Actions**。）
2. GitHub repo → **Settings → Secrets and variables → Actions → Variables →
   New repository variable**：
   - 名稱：`GAME_SERVER_URL`
   - 值：Render 給的網址，例如 `https://whack-a-mole.onrender.com`（**結尾不要斜線**）
3. push 到 `main`，`.github/workflows/deploy-pages.yml` 就會自動：
   規則單元測試 → 把 `GAME_SERVER_URL` 注入 `public/js/config.js` → 佈署到 Pages。

也可以到 **Actions → 佈署前端到 GitHub Pages → Run workflow**，
在欄位裡臨時填一個不同的伺服器網址（測 staging 用），不會動到 repo 變數。

### 伺服器位址的設定方式（優先序由高到低）

`public/js/config.js` 是**全站唯一**的連線設定入口，`app.js`、`online.js`、測試都不准自己寫死網址。

| 優先序 | 方式 | 什麼時候用 |
|---|---|---|
| 1 | 網址參數 `?server=https://xxx.onrender.com` | 臨時測 staging、跨電腦除錯 |
| 2 | 建置注入（GitHub Actions 用 `GAME_SERVER_URL`） | **正式用這個** |
| 3 | 同源（頁面本身就是伺服器送出來的） | 本機 `npm start` |

格式檢查是硬的：只接受 `http`／`https` 的絕對網址，`https` 頁面不接受 `http` 伺服器
（混合內容會被瀏覽器擋掉），格式不對就停用線上功能並顯示原因，
**不會靜默回退到 localhost 或任何寫死的網域**。

手動注入（本機模擬 Pages 建置）：

```bash
node scripts/inject-server-url.js https://whack-a-mole.onrender.com
node scripts/inject-server-url.js --allow-local http://localhost:3030   # 本機測試
node scripts/inject-server-url.js --clear                              # 還原成同源
```

### 免費方案的限制（設計時已經考慮進去）

- **會休眠**：閒置約 15 分鐘後服務會睡著，第一次連線要等十幾秒喚醒。
  前端的 `/health` 檢查逾時放寬到 10 秒，大廳也會顯示「冷啟動可能要十幾秒」。
- **檔案系統是暫時的**：房間**只存在記憶體**，不寫任何檔案。服務重啟房間就消失，這是預期行為。
- **有 CPU／頻寬配額**：對局是 50ms tick + **事件推播**（不是每幀送完整狀態），
  中間的升降動畫由前端依 `spawnAt` / `expireAt` 自己內插；
  每秒補一次完整狀態，補掉任何漏收的事件。空房 2 分鐘、打完 10 分鐘沒人動就自動回收。

## 測試

```bash
npm test              # 規則單元測試（177 項，不用開伺服器）
npm run test:online   # 線上流程實測（67 項，真的開伺服器 + 多個 socket 用戶端）
npm run test:leave    # 離開確認流程（單機與線上都會先問一句，確認後立即回首頁）
npm run test:board    # 各裝置盤面列欄與選項一致性
npm run test:sync     # 地鼠本體與分數標記出現／消失同步
npm run test:sidebar  # 切換側欄分頁後操作列仍固定
npm run test:invite-nick # 被邀請者進房前設定玩家暱稱
npm run test:reconnect # 斷線重連回同一間房、房主離開後接手再開一局
npm run test:browser  # 版面與流程實測（574 項，需要 playwright）
npm run verify        # 九個一起跑
```

`npm run test:browser` 需要先裝瀏覽器：

```bash
npm i -D playwright && npx playwright install chromium
```

**檢查順序依實際使用情境排：平板 > 桌機 > 手機。**
九種尺寸／方向都會檢查，截圖存到 `screenshots/`：

平板直向 768×1024・平板橫向 1024×768・大平板直向 834×1194・大平板橫向 1194×834・
桌機 1440×900・寬桌機 1920×1080・手機直向 390×844・手機橫向 844×390・小手機 360×640

每種尺寸都驗：不可水平溢出、設定鈕在安全區內且 ≥44px、設定鈕不被遮住、
觸控命中區足夠、地洞 ≥44px、盤面不超出可用範圍也沒浪費空間（會實際量「用掉可用空間的幾成」）、
側欄不超過 33% 寬且不遮住盤面、側欄行為（寬版固定／窄版抽屜）、
設定彈窗的焦點鎖定與 Escape 關閉、主控台不可以有未處理錯誤。
另外還會跑完整的單機一局、設定持久化，以及三個分頁（房主／玩家／觀戰）的線上流程。

```
│  ├─ leave-check.js         離開確認流程實測
│  ├─ board-check.js         各裝置盤面一致性實測
│  ├─ sync-check.js          地鼠與分數標記同步實測
│  ├─ sidebar-check.js       側欄分頁與操作列固定實測
│  ├─ reconnect-check.js     斷線重連與房主接手實測
│  ├─ invite-nick-check.js   邀請進房前設定暱稱實測
│  └─ browser-check.js       版面與流程實測（Playwright）
├─ tests/verify.js           規則單元測試
├─ .github/workflows/        CI + GitHub Pages 自動佈署
├─ render.yaml               Render 藍圖

```

### 兩個原則

1. **規則只有一份。** `rules.js` 前後端共用（瀏覽器 `<script>`、Node `require`），
   單機、線上、AI 全部走同一支 `Rules.whack()`，不會有兩套互相漂移的規則。
2. **線上一律伺服器說了算。** 用戶端送的只是「我敲了第幾號洞」的意圖，
   加不加分、加多少、地鼠死了沒，全部由伺服器判斷；
   `you.can.*` 權限旗標也是伺服器算好才給前端，前端只照著開關 UI。
   前端收到事件後只會沿用伺服器算好的分數，不自己重算。

隨機性全部走可注入的種子亂數，所以同一個種子會長出同一場地鼠 —— 重播、AI 測試、
多人同步都可以重現（對局畫面左下角的「種子」就是它）。

- 美術與音訊都是程式畫／程式合成的，沒有用任何外部素材。
  要換成正式插畫或音檔的話：造型在 `svgui.js` 的 `MOLE_ART`，音效在 `audio.js` 的 `SFX`。
- 沒有跨裝置的永久排行榜（免費方案的檔案系統是暫時的）。
  戰績只存在各自瀏覽器的 localStorage。要做的話需要接一個明確支援免費方案的資料服務。
- 沒有帳號系統，暱稱是訪客暱稱，靠 localStorage 的 clientId 認人（同一台裝置重連得回原位）。
